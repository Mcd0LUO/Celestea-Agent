## 一句话
在消息里**选中一段文字**，点浮标「引用」，这段内容就会作为**内容快照**挂到输入框上方，随你的下一条消息一起发出。

## 怎么用
1. 用鼠标选中任意消息（你 / Studio / 工具输出 / 系统回执）里的一段文本。
2. 选区旁出现浮标「引用」（`apps/web/src/ui/quote/select.ts:161-167`，点击处理在 `select.ts:147-155`）。
3. 点它 → 输入框上方出现一枚引用 chip（`apps/web/src/ui/quote/tray.ts:58-71`），可单条删除（`tray.ts:91-100`）。
4. 正常发送：引用会写进这条消息的文本里一起发出去（`apps/web/src/ui/send.ts:88,110`）；排队 / 插话路径同样（`send.ts:145,209`）。

浮标只在**当前聚焦会话**内、且落在正文 / 工具输出 / 思考段里时出现；输入框自身的选区会被排除（`select.ts:104-131`；`insideComposer` 在 `select.ts:41-43`）。

## 数据模型：内容快照，不是指针
引用保存的是**选中时刻的文本副本**（发送前还会按上限截断），不是「指向某条消息的链接」。所以：

- 原消息后来被压缩、清空、甚至删除，引用内容仍然完整；
- 引用随消息文本走，历史里能**解析回引用卡**重新渲染（`apps/web/src/ui/restore.ts:185`）。

序列化格式（定界行是 ASCII、全仓唯一；`apps/web/src/ui/quote/model.ts:60-62`）：

    ===== CELESTEA QUOTE =====
    [引用 1 · assistant · 第 3 轮 · Studio · 128B · trunc=0 · fmt=markdown]
    > 第一行
    > 第二行
    ===== CELESTEA QUOTE =====

- **header 字段**（`model.ts:156-169`）：序号、来源类型、轮次、来源标签、字节数、是否截断 `trunc`，以及可选的 `fmt` / `file` / `lines`。
- **正文**每行加 `> ` 前缀（`model.ts:171-176`）。
- **同形行转义**：正文里若出现定界串，行尾追加转义后缀 `[CELESTEA-QUOTE-ESCAPED]`，解析时反向剥离（`model.ts:145-154`）；转义与反剥离在行集合上是**双射**，往返后正文逐字不变。
- **往返口径**：文本级恒等 + wire 编码字段级恒等；`id` / `hash` / 会话 id / 锚点 / 选区偏移**不入 wire**（`model.ts:13-18`）。
- **上限**：单条 8 KiB、单条消息引用总量 32 KiB、最多 8 条（`model.ts:64-68`）；超限**显式截断**并在 header 标 `trunc=1`，不静默丢块。

## 零后端契约变更
引用**没有新端点、没有新字段**：它被序列化进用户消息的正文文本（`send.ts:110` 的 `serializeQuotes(...)` 结果直接作为这一轮的输入），与文本附件走同一条路径。后端、HTTP 契约、SSE 都不需要知道「引用」这个概念。

## 已知限制
（架构侧裁决 2026-09-19，见 `./iteration-f-capabilities.md` §6.8，均按「内容不丢」处理）

- **用户手打的合法块无法与真引用区分**：解析只在用户消息上、且要求「定界行 + `[引用 …]` header + 以 `> ` 开头的正文 + 闭合定界行」齐全；手工粘贴一个格式完全合法的块会被当作引用（内容不丢，模型仍看到原文）。
- **流式 assistant 选区**：正文每个渲染 tick 会重建，浮标只存「选区字符串 + 来源元数据」、不持有 Range；选区在点击前失效时浮标锚点可能过时（视觉偏移，不崩）。
- **hash 只存客户端、不入 wire**：历史解析出的引用 hash 为空（仅供渲染，不再进待发区；去重退化为文本键）。
- **总量上限由待发区守卫保证**；`serializeQuotes` 的防御性截断在**绕过待发区**直接调用时可能丢弃尾部块（正常路径不触发）。
